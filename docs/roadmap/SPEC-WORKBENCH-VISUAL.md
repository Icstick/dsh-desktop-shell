# 工作台视觉规范（FS / GIT 面）

- 范围：只约束工作台（文件管理 + 后续 git 面板）。不动 shell 其它面的既有主题。
- 状态：**待项目所有者拍板**（2026-09-13 起草）。
- 依据：Hermes 桌面六面观察（capabilities / messaging / artifacts / browse hub / 会话阅读器 / 外壳）
  + 本仓库既有暗色身份与画作。**只取结构语法，不取视觉身份。**
- 参考记录：`docs/roadmap/PLAN-FS-M2.md` 的对照表。

## 1. 语义 token（工作台作用域，先落地这一层）

| token | 用途 | 备注 |
|---|---|---|
| `--wb-surface` | 面板底色 | 与 shell 现有面板底一致 |
| `--wb-surface-raised` | 列表/编辑区 | 比底色略亮一档 |
| `--wb-border` | 分隔线、边框 | 发丝级；**选中态不用边框** |
| `--wb-text` / `--wb-text-muted` | 正文 / 副标题 | 副标题用于第二行、元信息 |
| `--wb-accent` | 活动元素（选中、tiak栏下划线、主按钮） | 只给活动态 |
| `--wb-ok` / `--wb-warn` / `--wb-error` | 状态四档中的后三档 | 绿/琥珀/红保持可辨识 |
| `--wb-status-*` | 状态条四档：normal / warn / bad / critical | 与运行时徽章同一套词汇 |
| `--wb-diff-added` / `--wb-diff-removed`（+ 词级） | **GIT-M1 预留** | 现在只登记名字 |

硬指标：正文与背景对比度 ≥ 4.5:1；组件里不写死颜色。

## 2. 结构（两栏 + 顶/底条）

| 区域 | 规格 | 内容 |
|---|---|---|
| 顶部工具条 | ~32 px | 刷新 / 显示隐藏项 / 全部折叠 + **内联快捷键提示** |
| 左栏（树） | 220–320 px，可拖 | 顶部**过滤框**（占位符教人，如 `Try 'crates'`）→ 根分区 → 树 |
| 右栏（视图/编辑） | 自适应 | 顶部**文档条**（文件名 + dirty 点 + 状态 chip）→ 正文 |
| 底部状态条 | ~28 px | 左：路径 · 编码 · 大小；右：**保存**（主操作靠右） |

## 3. 行制

- **树行**：名称 + 右对齐大小；类型 chip 仅用于链接；行高 ~28–32 px。
- **选中行**：柔和药丸底（`--wb-accent` 低透明度），**不加边框**；被选中的文件行额外显示一行灰色**根相对路径**。
- **目录行**：前置展开指示；展开状态用 `aria-expanded`。
- **列表行（GIT-M1 复用）**：名称 + 灰色一句话 + 右对齐动作。

## 4. 状态词表（chip 与状态条同一套）

`normal` / `warn` / `bad` / `critical` ↔ 编码异常、dirty、超限、冲突。
- chip 用于**头部**（编码 / 只读 / 冲突），状态条用于**底部汇总**。
- 只读原因必须可读到文字（“超过 2 MiB”“不是合法 UTF-8”），不用颜色单独表意。

## 5. 三态（每片必须都画）

- **空**：居中、可操作的一句话（教下一步），如“从左侧选一个文件”。
- **降级**：根不可用时显示**原因**（原文：the directory does not exist），并保留可用的根。
- **错误**：`role="alert"`，显示后端 message 原文（含 containment 拒绝原因）。

## 6. 交互约定

- 过滤框在树列顶部，纯前端过滤已加载列表；过滤生效时显示“N / M 条”。
- 截断要交代：`1-2000 of N` + 载入更多。
- 保存：仅 dirty 且可写时可用，底部状态条右端；`Ctrl/Cmd+S` 绑定并显示提示。
- 冲突：不静默覆盖；弹层给「覆盖 / 放弃 / 继续编辑」。
- 离开未保存内容时提醒。
- 右栏顶部文档条：FS-M2 单文档（名字 + dirty 点），多标签延后但位置留出。

## 7. 明确不取

配色、字体、图标语言、品牌词、YAML skin 机制、任何像素级模仿。
理由：本 shell 有自己的暗色身份与画作（CC BY-NC-SA），两套身份拼接只会更差。

## 8. 三个开放项（请拍板）

1. **根目录是否 chip 化**（Hermes 用来源 chip：Official / GitHub / Well-known…）。
   采用=切根不滚动、更像"工作区"；不采用=保持 FS-M1 的分区树。**默认建议：不 chip 化**（FS-M1 已可用，chip 化会改动已合并结构）。
2. **文档条（tab strip）是否 FS-M2 就做**。默认建议：**做单文档版本**（成本低、位置先定），多标签延后。
3. **底部状态条 vs 顶部元信息**。FS-M1 现在把「路径/大小/编码」放在视图**头部**；规范建议移到**底部**。
   默认建议：**移到底部**（与编辑器惯例一致），头部只留文档条 + chip。

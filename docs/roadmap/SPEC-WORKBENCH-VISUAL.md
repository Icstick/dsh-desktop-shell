# 工作台视觉规范（FS / GIT 面）

- 范围：只约束工作台（文件管理 + 后续 git 面板）。不动 shell 其它面的既有主题。
- 状态：**已拍板**（2026-09-13，三个开放项「照默认」）→ 落地记录见 §9。
- 依据：Hermes 桌面六面观察（capabilities / messaging / artifacts / browse hub / 会话阅读器 / 外壳）
  + 本仓库既有暗色身份与画作。**只取结构语法，不取视觉身份。**
- 参考记录：`docs/roadmap/PLAN-FS-M2.md` 的对照表。

## 1. 语义 token（工作台作用域，先落地这一层）

| token | 用途 | 备注 |
|---|---|---|
| `--wb-surface` | 面板底色 | 与 shell 现有面板底一致 |
| `--wb-surface-raised` | 列表/编辑区 | 比底色略亮一档 |
| `--wb-border` | 分隔线、边框 | 发丝级；**选中态不用边框** |
| `--wb-text` / `--wb-text-muted` | 正文 / 副标题 | 副标题用于第二行、元信息 |
| `--wb-accent` | 活动元素（选中、tiak栏下划线、主按钮） | 只给活动态 |
| `--wb-ok` / `--wb-warn` / `--wb-error` | 状态四档中的后三档 | 绿/琥珀/红保持可辨识 |
| `--wb-status-*` | 状态条四档：normal / warn / bad / critical | 与运行时徽章同一套词汇 |
| `--wb-diff-added` / `--wb-diff-removed`（+ 词级） | **GIT-M1 预留** | 现在只登记名字 |

硬指标：正文与背景对比度 ≥ 4.5:1；组件里不写死颜色。

## 2. 结构（两栏 + 顶/底条）

| 区域 | 规格 | 内容 |
|---|---|---|
| 顶部工具条 | ~32 px | 刷新 / 显示隐藏项 / 全部折叠 + **内联快捷键提示** |
| 左栏（树） | 220–320 px，可拖 | 顶部**过滤框**（占位符教人，如 `Try 'crates'`）→ 根分区 → 树 |
| 右栏（视图/编辑） | 自适应 | 顶部**文档条**（文件名 + dirty 点 + 状态 chip）→ 正文 |
| 底部状态条 | ~28 px | 左：路径 · 编码 · 大小；右：**保存**（主操作靠右） |

## 3. 行制

- **树行**：名称 + 右对齐大小；类型 chip 仅用于链接；行高 ~28–32 px。
- **选中行**：柔和药丸底（`--wb-accent` 低透明度），**不加边框**；被选中的文件行额外显示一行灰色**根相对路径**。
- **目录行**：前置展开指示；展开状态用 `aria-expanded`。
- **列表行（GIT-M1 复用）**：名称 + 灰色一句话 + 右对齐动作。

## 4. 状态词表（chip 与状态条同一套）

`normal` / `warn` / `bad` / `critical` ↔ 编码异常、dirty、超限、冲突。
- chip 用于**头部**（编码 / 只读 / 冲突），状态条用于**底部汇总**。
- 只读原因必须可读到文字（“超过 2 MiB”“不是合法 UTF-8”），不用颜色单独表意。

## 5. 三态（每片必须都画）

- **空**：居中、可操作的一句话（教下一步），如“从左侧选一个文件”。
- **降级**：根不可用时显示**原因**（原文：the directory does not exist），并保留可用的根。
- **错误**：`role="alert"`，显示后端 message 原文（含 containment 拒绝原因）。

## 6. 交互约定

- 过滤框在树列顶部，纯前端过滤已加载列表；过滤生效时显示“N / M 条”。
- 截断要交代：`1-2000 of N` + 载入更多。
- 保存：仅 dirty 且可写时可用，底部状态条右端；`Ctrl/Cmd+S` 绑定并显示提示。
- 冲突：不静默覆盖；弹层给「覆盖 / 放弃 / 继续编辑」。
- 离开未保存内容时提醒。
- 右栏顶部文档条：FS-M2 单文档（名字 + dirty 点），多标签延后但位置留出。

## 7. 明确不取

配色、字体、图标语言、品牌词、YAML skin 机制、任何像素级模仿。
理由：本 shell 有自己的暗色身份与画作（CC BY-NC-SA），两套身份拼接只会更差。


## 9. 落地记录（2026-09-13）

- 三个开放项按「照默认」拍板（2026-09-13）：**根不 chip 化**、**文档条做单文档版本**、**路径/编码/大小移到
  底部状态条**。三项均已在 FS-M2 / GIT-M1 落地。
- 新增 `workbench-ui` 承载 `Files | Git` 切换：真正的主键盘 tablist（←/→/Home/End 移动选择与焦点），
  当前视图的副标题放在切换条右端。**两个面板随之删掉各自的面板标题**——页面头 + 切换条已经说明了这是哪个面，
  面板体内再来一行「工作台 / Workbench」是纯重复。
- token 层从 `.file-manager` 提升到 `.workbench, .file-manager, .git-panel`，切换条与两个面板共用同一套词汇。
- `--wb-diff-added` / `--wb-diff-removed` 已启用；diff 行底色由
  `color-mix(in srgb, var(--wb-diff-*) 12%, transparent)` 派生，不引入第二个硬编码颜色。
- 仍待做（后续片）：左栏可拖拽调宽（长仓内路径会折行）、多标签文档条、面包屑。
- **高度顶满 + 描述一行（2026-09-13，验收反馈「界面没有上下顶满」「这句字体小一点、排一行」）**：
  `.shell-content:not(.shell-content--surface)` 原本钉死 `flex: none`——对文字类面是对的（短面板不该被拉伸），
  但让工作台浮在窗口上三分之一。现在工作台面把 flex 链一路接通到面板内部：内容区 → `.workbench` → `.workbench__panel`
  → `.file-manager`/`.git-panel` → `__body`（并解除两栏的 `max-height: 62vh` 上限），树与 diff/编辑器随窗口长高，
  底部状态条自然贴底；编辑器额外 `flex: 1` 吃掉视图面板的余量。页头描述 12.5 → **11.5 px** 并取消 `max-width: 40ch`
  （就是它把一句话逼成两行的）。**仍然只作用于工作台面。**
- **量宽放开（2026-09-13，项目所有者验收反馈「左右的空间也用起来」）**：`.shell-workspace` 在工作台面加 `--wide`
  修饰，把 shell 的 1200 px 量宽放开（`max-width: none`）——页头与内容区同宽，两者保持对齐。理由：1200 px 是为
  文字类面（设置/运行时）定的，树 + diff/编辑器是工具，宽窗上不该是一座孤岛。**只放开工作台面**，其余面不变。
- **切换条副标题去掉（同日反馈「副标题的小字可以拿掉」）**：`workbench__subtitle`（「环境关联的文件」/
  「环境关联的仓库（只读）」）删除，切换条只剩 tab 本身；`fs.subtitle` / `git.subtitle` 两个 key 随之成为死键并删掉。
- **页头收小（2026-09-13，项目所有者验收反馈「banner 可以小一点」）**：工作台面的 `.shell-header` 加 `--slim` 修饰
  （222 → 150 px、标题 32 → 24 px、内边距 34/38 → 22/30），插画与描述保留。不采用 `--compact`——那是 dsh/terminal
  沉浸面用的扁平条，会把插画和描述整个去掉。**只作用于工作台面**，其余面不动；1050 / 780 px 断点各有对应收小值。

## 10. GIT-M2 的写入控件（2026-09-13）

- 行内动作（暂存 / 取消暂存 / 放弃改动）**始终在 DOM 里且在 Tab 序内**，只是压暗到 0.5，
  hover / focus-within / 选中行恢复 —— 不用 `display: none` 藏，否则键盘就够不着。
- 「全部暂存 / 全部取消暂存」放在**改动**这一层的标题栏：后端只接受"一条路径"或"全部"，
  挂在分组头上等于承诺了一个它表达不了的范围。
- **破坏性动作用键入式确认**：弹层里要输入 `git.discard.word`（zh「放弃」/ en「DISCARD」）才解锁确认按钮；
  这是全站唯一一个会丢工作区改动的地方，所以它必须比一个点击更贵。
- 提交框属于索引而不属于选中的文件，因此放在 diff 选择分支之外、常驻视图底部（diff 滚动、它不动）。
- 禁用态必须看起来禁用：`.git-panel__action:disabled` 降到 0.4 不透明度（第一次截图里它和可点的按钮长得一样）。

## 8. 三个开放项（请拍板）

1. **根目录是否 chip 化**（Hermes 用来源 chip：Official / GitHub / Well-known…）。
   采用=切根不滚动、更像"工作区"；不采用=保持 FS-M1 的分区树。**默认建议：不 chip 化**（FS-M1 已可用，chip 化会改动已合并结构）。
2. **文档条（tab strip）是否 FS-M2 就做**。默认建议：**做单文档版本**（成本低、位置先定），多标签延后。
3. **底部状态条 vs 顶部元信息**。FS-M1 现在把「路径/大小/编码」放在视图**头部**；规范建议移到**底部**。
   默认建议：**移到底部**（与编辑器惯例一致），头部只留文档条 + chip。
